Pia-Translate

GitHub ↗ 다운로드 페이지 ↗

인터넷도, PC도 없이 폰 안에서 완전히 로컬로 동작하는 번역 앱 — 5개 Pia 계열 중 가장 오래, 가장 깊게 디버깅한 프로젝트다.

Main Features

  • Flutter + ONNX Runtime으로 서버 없이 폰 안에서 완전히 로컬로 번역
  • 텍스트·음성·이미지(OCR) 3채널 입력 지원
  • 직접 지원 안 하는 언어쌍은 영어를 경유(ko→ja는 ko_en+en_ja를 순차 실행)
  • 번역 모델은 반드시 상업적 이용이 가능한 라이선스(Apache-2.0/MIT)만 채택 — 품질이 더 좋아도 NLLB 같은 비상업 전용(CC-BY-NC) 모델은 제외
  • 번역 기록을 중앙 DB(pia_dataset)로 동기화해 Pia의 학습 데이터로 재사용
  • GitHub Actions가 모델 변환부터 APK 빌드·릴리스까지 자동화

디버깅 여정 — BUG-001~004

  • "real real real…" 무한 반복 — 디코더에 반복 억제가 없어서였다. no-repeat-ngram + repetition penalty로 해결.
  • "안녕하세요" → "여호와하나님" (BUG-002, 근본 원인 규명) — HuggingFace 토크나이저는 공유 vocab.json으로 단어를 관리하는데, 네이티브 코드가 SentencePiece 내부 id를 그대로 ONNX에 넣고 있었다. 완전히 다른 단어가 나오는데도 "언어는 맞으니" 겉보기엔 번역이 되는 것처럼 보여 한동안 못 잡아냈다.
  • "Hi Hi Hi…" 무한 반복 (BUG-004, 진짜 근본 원인) — 처음엔 INT8 양자화 탓으로 추정하고 완화값만 늘려 덮었다. 나중에 양자화 없는 FP32 원본으로 직접 재현해보니 진짜 원인은 인코더 입력 끝에 EOS 토큰을 안 붙인 것이었다. 붙이자 즉시 정상 종료됐다. 교훈: 원인 진단은 항상 양자화 없는 원본으로 먼저 재현해, 양자화 문제인지 코드 문제인지부터 갈라놓을 것.
  • 영→한 폴백 모델의 번역 품질이 나빠서("hello world"→알아볼 수 없는 결과) Apache-2.0 라이선스의 다른 모델로 교체.

Known Issues · Next Steps

  • 영어는 어느 정도 정확하지만, 중국어·일본어는 정확도가 많이 떨어지는 편
  • 폰 자체 내장 언어팩만으로는 정확도가 부족해 이를 보완할 방안을 모색 중
  • 실기기(갤럭시 S22) 최종 검증 도중 중단 — adb로 영문을 입력해도 실제로 입력이 안 되는 현상 확인 중(소프트키보드가 한글 모드였을 가능성), 재개 지점만 문서로 남겨둔 상태
