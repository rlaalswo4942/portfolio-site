지금 상태 · 운영 중

운영 중. 날짜별 백업도 남기고 있습니다.

기능 자세히
  • 음성 파일·글·레이블 자료 저장. 같은 파일이 두 번 들어오면 파일마다 고유한 지문(SHA-256)을 비교해 알아챔
  • 인터넷 위 Neon 데이터베이스(싱가포르 서버)가 유일한 원본. 메인 컴퓨터 전원과 상관없이 모든 기기가 같은 창고 하나에 접속
  • 창고 내용을 통째로 뜬 백업 파일(pg_dump)을 날짜별로 저장소에 올려 보관하고, 되살리는 방법도 문서로 정리
  • 모든 프로젝트가 함께 쓰는 작업 기록(dev_logs)과 기능·버그·할 일 목록(dev_items)도 운영. "백업해" 한마디면 여기에 기록이 쌓임
  • 다른 프로젝트가 이 창고에 연결할 때 그대로 복사해 쓰는 연결 코드 본보기(Python·TypeScript·Dart) 제공
가장 근본적이었던 사고

한때 내 컴퓨터의 작업 폴더가 "데이터베이스"와 "데이터베이스 (1)" 두 개로 갈라져, 같은 기능을 양쪽에서 따로 다시 만들고 있었습니다. 원인은 "바뀐 것 없음"이라는 표시(git status)만 보고 인터넷 저장소와 똑같다고 착각한 것이었습니다. 실제로는 인터넷 저장소에 옛날 버전만 있었고, 더 발전된 내 컴퓨터 버전은 한 번도 올라간 적이 없었습니다.

두 버전을 합쳐(git merge) 해결했고, 이후 원칙을 정했습니다. "여러 기기·여러 창에서 작업할 땐 시작 전에 항상 인터넷 저장소의 최신 상태를 받아 와 양쪽 차이를 직접 확인한다." "폴더를 복사해서 동시에 따로 작업하지 않는다."

Railway에서 Neon으로 옮기기 (2026-10-05)

바깥에서 접속하려고 따로 두었던 복사본 데이터베이스(Railway)가 멈춰 있어서, 어느새 내 컴퓨터의 데이터베이스가 유일한 사본이 되어 있었습니다.

먼저 전체를 백업 파일로 떠서 임시 창고에 되살려 보고 자료 개수가 맞는지 확인한 뒤 저장소에 보관했습니다. 그다음 같은 백업으로 Neon에 되살리고, 8개 표의 내용이 원본과 똑같은지 지문(체크섬)으로 확인한 뒤 원본을 옮겼습니다. 사본이 둘이면 언젠가 서로 어긋난다는 앞선 사고의 교훈대로, 이번에는 복사본을 따로 두지 않고 창고를 하나만 씁니다.
